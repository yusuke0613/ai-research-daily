### Claude Code Opus 5 の Auto Mode、間接プロンプトインジェクションで突破される
**何が起きた**: セキュリティ研究者 Johann Rehberger 氏(wunderwuzzi)が、Claude Code の Auto Mode に対する間接プロンプトインジェクションの実証を公開した。攻撃は「このWebページを要約して」という無害な依頼から始まる。ページはZIPアーカイブへリダイレクトされ、その中には復号用バイナリと `struct.py` という悪意あるPythonファイルが同梱されている。Claudeが同梱デコーダを動かす際、Pythonがカレントディレクトリを先に探索する仕様により標準ライブラリの `struct` が乗っ取られ、import時点でコードが実行される。そこから別プロセスが後続ペイロードを取得してC2コールバックを張り、痕跡として電卓を起動する。少数の試行で成功率60〜80%と報告されている。
**なぜ重要**: Anthropicは以前、固定シナリオ集に対するAuto Modeのプロンプトインジェクション成功率を0.00%と示していた。今回はその主張を否定するものではなく、「無害に見える手順を積み重ねる多段攻撃は分類器の想定外」という限界の実演になっている。Anthropicはこの報告を Informative としてクローズし、想定通りの動作だと回答。本当の防御境界はOSレベルの隔離と外向き通信の制御にあるという立場を示した。
**自分・社内への影響**: エージェントに自動実行を許すなら、防御はエージェントの内側(承認プロンプトや分類器)ではなく外側に置く。コンテナ/VMでの実行、egress制限、ホームディレクトリ・SSH鍵・クラウド認証情報を実行環境から外す、の3点が最低ライン。
出典: https://embracethered.com/blog/posts/2026/breaking-claude-code-opus-5-and-automode/

### Debian、生成AIの「責任ある利用」を一般決議で可決
**何が起きた**: Debianの一般決議 2026-002 で、Marc Haber 氏提案の「Responsible Use of Generative AI」が採択された。投票は8月15日〜28日、有効票はおよそ450票で、賛否は64%対36%と割れた。決議は生成AIの利用を推奨も禁止もせず、貢献者に対し「AI支援の出力を理解し、レビューし、テストし、必要なら修正したうえで取り込む」ことを求める。人間のレビューなしにAI生成物をそのままアップロードする行為は、Debianの開発慣行に反すると明記された。
**なぜ重要**: 大規模OSSコミュニティが、ツールの可否ではなく「成果物に対する人間の責任」を規範として明文化した点が実務的。禁止に踏み切ったプロジェクトが相次ぐ中で、Debianは責任所在を貢献者に置く形で折り合いをつけた。
**自分・社内への影響**: 社内ガイドラインを作る際、「どのツールを許可するか」より「レビューと責任の所在をどう定義するか」を先に書くほうが、モデルやツールが入れ替わっても陳腐化しない。
出典: https://www.debian.org/vote/2026/vote_002

## 今日の基礎

### トークンとは何か: 料金・速度・制限のすべての単位

**一言でいうと**: トークンは、LLMにとっての「文字数」ではなく「マス目」です。原稿用紙が1文字1マスなのに対し、LLMの原稿用紙は「よく使う単語なら1マス、珍しい語や日本語なら細かく分割して複数マス」という不均一なマス目でできています。料金も、速度も、入力できる長さの上限も、すべてこのマス目の数で数えられます。

**仕組みの要点**: モデルは文字そのものを読んでいるのではなく、テキストをトークナイザで分割した「トークンID列」を読んでいます。英語は頻出語がまるごと1トークンになりやすく、おおむね1トークン≒4文字程度。一方、日本語は文字種が多く分割が細かくなるため、**1文字あたり1〜2トークン**が目安です。つまり同じ内容でも日本語は英語よりトークンを食いやすい。ここで押さえるべきは、料金が入力トークンと出力トークンで別単価になっていること、そして出力単価は入力の数倍に設定されるのが一般的だということです。コンテキストウィンドウの上限も文字数ではなくトークン数で切られるため、「日本語10万文字の資料を丸ごと渡せるか」は、単純な文字数ではなくトークン換算で判断する必要があります。

**実務でどう効くか**: 概算は「日本語の文字数×1.5」で十分実用になります。たとえば1万文字の議事録を要約させるなら入力は約1.5万トークン、出力を2千文字とすれば約3千トークン。これに各モデルの100万トークンあたり単価を掛ければ1件あたりのコストが出て、月間件数を掛ければ稟議に載せる数字になります。見積もりで事故りやすいのは、①毎回同じ長いシステムプロンプトを送っている(プロンプトキャッシュの検討対象)、②RAGで検索結果を大量に詰めている、③エージェントが会話履歴を毎ターン再送している、の3つ。いずれも「入力トークンが静かに膨らむ」パターンで、体感速度の低下としても現れます。コスト調査の第一歩は、まず実際のリクエストのトークン内訳を測ることです。
